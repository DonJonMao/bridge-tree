# Evidence Bridge v3 修改计划与验收

日期：2026-09-30。状态：实现与验证完成，正在核对 GitHub 交付；逐项结果记录在 `evidence_bridge_v3_validation.md`。用户已授权按日志完成方法修改、保证可运行与鲁棒、详细记录模块状态并推送 GitHub。本轮不以先取得效果提升作为实现前提，也不将离线测试当成准确率提升的证明。

## 1. 依据与必须解决的问题

本次 v2 导出含 532 个权威 outcome，与当前源码和数据 hash 一致。73 个 normal 成功同题中 dense 55 对、EB 52 对；dense 876 条原文全部在 EB 候选池，668 条在映射阶段失去选择资格。两方法选集并集 73/73 都能放入同一 8192 reader 预算，因此原文删除不是容量所迫。flashcards/推荐书有任务需求错位，绘画课在已有正确需求下仍漏映射。normal 中 10 个空选集，不代表证据充分。

31 个 EB 失败中 26 个包含 inferential→explicit 覆盖类型错误；9 个首次选择失败后因修复附加字段超过 16384 而未能发出修复。全部 177 个 EB 顶层 evidence_calls 漏记为 0。完整病例、成本与边界见 `reports/2026-09-30-dense-evidence-audit/ACTUAL_REPORT.md`。

## 2. 范围与不变条件

- 保持当前搜索调度、四项 A 算术、ANN/集合预算和 gap 机制；不增加搜索框架。
- reader 模型、提示、输出上限与 8192 输入预算不变；证据模型总调用仍最多 24。
- planner 仍只看 query；所有证据模块均不读取选项/gold。历史 cutoff、权威角色、引用来源、原文 reader 保持。
- 不静默回退 dense，不编造映射/covered，不把未评估写成无关。
- v3 在独立输出/缓存/后台状态和新包名下启动。旧 v2 结果只读保留，源码/配置变更不得混入旧 run resume。

## 3. 按顺序实现的改动

### P1：修正个性化任务理解

重写 PLAN/MAP/SELECT 的任务说明：用户近况陈述需要与相关个人历史衔接，不自动将名称、地点、时间、安排设为必要信息。推荐所需的用户偏好是证据，原文不必已经含完整推荐答案。根据真实 query 决定是否需要早期经历、阶段变化、原因、限制及跨领域偏好；不对所有题硬套变化原因模板。需求仍冻结，避免本轮同时引入动态重规划。

验证：协议保持 query-only；版本/prompt identity 更新；对既有日志错误类型建立回归场景。实际语义效果由后续固定输入真实服务小样本记录，不能通过字符串断言声称有效。

### P2：给原文独立复核机会，减弱映射否定的淘汰权

正式 executor 按与 dense 完全相同的预算可行规则生成 `baseline_ids`，交给 evidence selector。启用 `raw_memory_review` 时，selector 请求在证据 ledger 之外直接展示这些真实记忆及权威角色/顺序信息。即使没有映射，这些已展示原文的 ID 仍可选择；不强制最终全选，不创建虚假的证据映射。

选择输入先容纳完整的基准原文记录，再按现有轮转规则填入 ledger；超过输入上限按完整记忆/事实记录省略并明确记日志，不剪 JSON 或静默截断原文。不可见 ID 仍禁止选择。覆盖引用仍只能使用已验证、同需求、属于最终选集的 ledger；选入未映射原文不自动生成 covered。`raw_memory_review=false` 可作为独立机制消融，候选集和预算不变。

验证：被 mapper 合法判无关的已召回原文确实进入最终选择请求并可以到 reader；没有来源引用不会自动获得覆盖；未展示/未来/未知 ID 仍拒绝；全文过长有确定预算行为。对原始日志 D/S/并集预算及关键历史建立无模型离线回归。

### P3：覆盖类型、局部修复与有界降级

- 已验证引用的 kind 由代码保守约束：含 inferential fact 的 explicit 只能降为 inference；独立 partial 联合覆盖同样必须 inference。模型 inference 不升为 explicit；不修改事实 relation，不制造 support；单 partial、重复切片、contradiction 不能因此伪造 covered。保留模型声明与规范化原因。
- 覆盖局部修复只发送未验证需求、固定选集、对应合法 ledger 及错误反馈，不重发全候选原文和无关 ledger。每次实际输入检查预算；修复仍无法容纳时记录真正的预算原因，不隐藏在旧关系错误里。
- 映射为最终选择、局部修复及预算修订预留调用和全局 repair 额度，总调用仍受 24 限制。
- 启用 `allow_unassessed_coverage` 时，仅在选集 header 合法且失败限于覆盖说明、有限恢复耗尽后，保留有效行，将其余行标为内部 `unassessed`、`validation_complete=false`，继续最终 reader 容量检查。保存原错误、恢复动作、尝试与降级状态。不能称作完整验证完成。
- 未取得合法选集、不可解析全局响应、未知选中 ID、最终 reader 超限、拒答或服务故障仍按明确失败处理，不能被该降级吞掉。

验证：26 类类型错误的保守规范化、9 类修复超限原始形态重放、错误引用不变成支持、降级不隐藏失败原因、非法 header/服务异常不继续 reader、预算有界。

### P4：成本和模块可观测性

修复原生 `complete_evidence_messages` 计数，顶层证据次数与 selector 实际逻辑调用一致，reader 独立，失败尝试计费。

任务 artifact 与 live/snapshot 日志必须可追踪：baseline/candidate/fully_mapped/eligible/raw_review_visible/selected ID；原文复核被输入预算省略的 ID；每条候选去向；coverage 声明/有效 kind；局部修复范围、输入预算、成功/失败；未评估覆盖的具体需求和原因；最终是否空上下文、是否仅原文/映射混合、baseline 保留率；实际调用和延时。

汇总保留旧 reliability 维度，同时另列语义证据状态和 coverage 完整性，不能让 `normal` 或成功掩盖 empty/unassessed。模块事件字段进入 allowlist，不只存在内存。继续以当前 outcome 去重，不累计 live 和快照重放。

### P5：版本交付与验证

更新正式实现契约、运行手册、v3 配置/包名/默认目录，保留历史文档标识。提供容易粘贴的状态和模块诊断命令。计划与验证记录同步，不预写已完成。

依次运行：有意义的选择/修复/成本单元回归 → 正式 executor 的真实控制流集成与本地 HTTP 协议测试 → 真实导出离线回归 → 全套 pytest/静态检查 → Linux 脚本与包内容检查 → 若配置服务可访问，运行有界真实 plan/map/select/reader 开发烟测并记录原始产物。真实服务不可用时如实记录具体阻断，不用 fake 结果冒充真实验证，继续完成其余可验证工作。

最后核对 git diff、已有用户文件未改、敏感配置/原始大日志未加入提交，提交到当前工作分支并 push `origin`；远程 head 与本地提交一致才算推送完成。
