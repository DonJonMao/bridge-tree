# BridgeTree 机制改进：2025–2026 顶会调研与实验方案

日期：2026-09-23。研究对象是当前 `dependency_*` 路径及 2026-09-22 导出的部分运行日志。本次新增公开文献核验与方案设计；未修改算法、配置或旧结果，未调用用户的 embedding、reranker、reader 服务。embedding/reranker 超长按用户要求暂不讨论。

本文保留实现前的阶段性调研结论与实验建议。后续已完成的具体方法、配置和验证以 [实现契约](../../docs/evidence_bridge_implementation.md) 和 [源码审查记录](../../docs/evidence_bridge_review.md) 为准。

## 1. 判断与优先级

最值得做的是两个互相独立、之后可以组合的改动：

1. **让未探索目标获得明确的预算机会。** 当前所有根优先级为 0，正后继总能抢在其他根之前；这套规则本身会造成单目标垄断。先在原评分器下改调度，便于判断覆盖是否带来收益。
2. **让“回答缺什么证据”决定集合选择。** 正 activation 是条件交互的变化，原 query relevance 是主题匹配；二者都不能直接代表历史证据是否足以回答。对原因、变化和阶段问题，需要显式保留有出处的历史信息，并允许整组选择。

对 activation 增加边际门槛值得单独验证，但不是全部机制问题的答案。日志中 9,862 次正 activation 只有 382 次目标新边际非正（约 3.9%），而 88.33% 的成功 activation 任务只访问一个根。二者的统计单位不同，不能直接归因；至少说明只过滤这 382 条记录，不能据此宣称解决了普遍的预算垄断。

已测 P/PG 等集合归档遗漏作为共同的实现修复基线；**把遗漏集合补进 archive**与**允许搜索更换目标、选择器删除/替换**分开。后两者改变算法可达路径。本报告不把修正解析、归档后的收益算作新机制收益。

## 2. 当前机制暴露了什么

令 `P` 为已选前提，`e` 为目标，`G` 为新增前提组，当前分数为 `R`：

\[
M_e=R(P\cup G\cup\{e\})-R(P\cup G),\quad
M_G=R(P\cup G\cup\{e\})-R(P\cup\{e\})
\]

\[
A=M_e-[R(P\cup\{e\})-R(P)].
\]

`A>0` 仅表示 e 的条件边际变大；`M_e>0` 才表示此时保留 e 对 **R** 有正贡献。两者均未证明回答效用。

- 日志中的实际例子：`R(G)=0.558327`，`R(G+e)=0.538983`。虽然 A 为正，强行保留 e 的分数反而更低。固定目标会把一个找到有用 G 的过程解释成“原目标被激活”。
- flashcards 原因题：当前表态得分约 0.999617，加回“过去不利于深度学习”的历史后降至约 0.997409。它说明仅修正 activation 的符号门槛，仍无法处理评分目标与历史证据的错位。
- 所有 759 个成功搜索任务耗尽 ANN；通常初始阶段花 13/36 次，剩 23 次条件检索。不能把 23 次均摊给约 22 个根后，就认为同时解决了覆盖与深入。

还有一个数学边界：四项差分需要对分数差值有解释，仅有正确排序并不够。人为示例 `R(P),R(Pe),R(PG),R(PGe)=(.1,.2,.3,.45)` 的 A 为 +.05；严格递增的平方根变换保留所有集合排序，却把 A 变为约 −.007888。这是说明量纲问题的例子，**不是日志观测**。它不意味着应该改成平方根或 logit；反而说明不能靠任意变换声称找到了真实互补性。

## 3. 论文依据与可借用部分

正式录用身份以官方会议页、ACL Anthology 为准；方法细节以论文正文为准。论文在数学、代码或其他记忆数据集上的收益不作为本项目收益预测。详细逐篇核查见本报告最后链接的三份调研笔记。

### 3.1 SETR：先识别信息需求，再整体选集合

**Shifting from Ranking to Set Selection for Retrieval Augmented Generation，ACL 2025 主会。** [官方论文](https://aclanthology.org/2025.acl-long.861/)，正文 §3.2、Figure 2，印刷页 17608–17609。

方法把流程拆成三步：列出回答 query 所需的信息；为每项需求定位 passages；选择共同覆盖需求的证据子集。它不是把 passages 分别打分后取 top-k，也不要求选出的集合保留此前已选项。

**可借用的是信息需求—证据映射和整体选择。** 原文有 GPT-4o zero-shot 提示流程，但正式 SETR 使用 40K 教师标注样本蒸馏训练 Llama-3.1-8B，不能称整套方法无需训练。我们可以试提示式版本，必须单列新增推理成本及其证据判断错误。论文的多跳开放域问题也不等同于个性化陈述式 query。

### 3.2 AB-MCTS / BG-MCTS：把开新分支与继续深入分成动作

**Wider or Deeper? Scaling LLM Inference-Time Compute with Adaptive Branching Tree Search，NeurIPS 2025** 提出 AB-MCTS。[官方会议页](https://neurips.cc/virtual/2025/poster/116491)，[全文](https://arxiv.org/html/2503.04412v3)。其 §3 的 GEN 表示生成新分支，CONT/已有子节点表示继续细化；“新分支”不是一个永远输给已评分节点的零优先级占位符。

**Aligning Tree-Search Policies with Fixed Token Budgets in Test-Time Scaling of LLMs，ICML 2026** 提出 BG-MCTS。[官方会议页](https://icml.cc/virtual/2026/poster/63795)，[OpenReview](https://openreview.net/forum?id=TgaVuBX8dx)。§3 将剩余预算比例引入探索策略，前期较广探索，后期更多细化与完成。

可迁移的是**显式选择新目标或深入旧目标，以及预算参与策略**。不能直接搬贝叶斯奖励后验、UCB 保证或深度奖励：AB-MCTS 明确要求可靠评价器；BG-MCTS 的完成度/推理深度不等于我们的记忆条数。当前 R 未经回答效用验证，且 ANN 次数、逻辑集合评分、reader 输入成本也不相同。

BG-MCTS 的主要验证是数学推理；其附加物理任务用到参考答案评价，不能用该结果为我们的答案不可见评分协议背书。论文主要计输出 token，输入与评分器成本也没有完全覆盖。我们借的是预算策略思想，而非其结果或成本口径。

### 3.3 条件贡献研究的一个重要限制

**SCARLet，EMNLP 2025 主会**，[官方论文](https://aclanthology.org/2025.emnlp-main.33/)，使用多个 passage 子集的 mask 和 gold-token 输出拟合贡献，随后训练 retriever。**InfoGain-RAG，EMNLP 2025 主会**，[官方论文](https://aclanthology.org/2025.emnlp-main.365/)，其 §3.1.2 的信息增益使用 ground-truth answer，随后训练 reranker。

这些方法支持区分相关性与生成贡献，但不能把论文里的 gold answer 条件分数直接搬进当前在线检索。也不建议偷偷换成模型自己猜的答案再优化其概率：那容易偏向支持初始猜测的记忆。这里将它们作为机制依据与排除项，不作为首版实现方案。

### 3.4 REMem / MRAgent：历史可共存，线索可改变

**REMem: Reasoning with Episodic Memory in Language Agent，ICLR 2026。** [官方会议页](https://iclr.cc/virtual/2026/poster/10008195)，[全文](https://arxiv.org/html/2602.13530v3)。§3.1 明确保留随时间加入、可能互相矛盾的事件概述和事实，供历史回访；§3.2 使用时间范围、排序和事件上下文查询。

对当前项目，应借“按所问阶段解释旧观点”，而非简单提高新近记忆权重。原始历史目前本就没有被覆盖删除，问题发生在候选评价和最终选择；因此先给已召回历史标明来源、阶段和支持作用，不必重建完整图。不要把 source order 当真实事件时间，未知时间就保留未知，也不要从先后关系推断因果。

原论文没有 PersonaMem，且需要 LLM 索引；迭代版还有在线推理。其简单回忆任务上单步版反而比迭代版好，复杂时间推理才更需要多步。论文自己仍发现“已召回证据却拒答”的错误，因此不能认为引入结构或判断器就自动解决终端使用问题。

**Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents，ICML 2026。** [官方会议页](https://icml.cc/virtual/2026/poster/60697)，[全文](https://arxiv.org/html/2606.06036v1)。MRAgent §4 的 `Content → (Cue, Tag)` 反向访问，让新内容引出新的检索线索。对项目可借为有限次数的 target pivot / 新根晋升，而不是始终携带原目标 e。

当前已经有 `q+e+P` 条件检索，不能把它描述成完全静态；真正限制是 e 固定、外部发现不成为新根。先试纯结构性的“外部新 ID 可成为新根”，之后再测语义驱动 pivot。前者不新增 LLM，却不能判断哪个转向有意义。MRAgent 自己的证据 H 仍做 union 累积，**它不是删除/替换最终集合的文献依据**；全文还包含显著的 LLM 写入和工具推理成本。

### 3.5 RGMem / RF-Mem：有直接记忆任务依据，但只借局部机制

**RGMem: Renormalization Group–inspired Memory Evolution for Language Agents，ICML 2026** 已在本次核验正式录用。[官方会议页](https://icml.cc/virtual/2026/poster/65195)，[全文](https://arxiv.org/html/2510.16392v3)。§3.3 的 `(Σ,Δ)` 分开保存主要模式和冲突、例外、变化信号，适合启发“不要用单一当前观点吞掉历史差异”。

它确实测试 PersonaMem，但用 128k，不是当前 32k；原因回忆类别相对次优仅约 +0.7～0.9 个百分点，不能以总体结果宣称已经解决原因题。附录平均每 session 约 979 次 LLM 调用，含构建维护检索生成；这里不建议整套移植。若以后加入摘要，保留差异和出处有价值，但任何派生记忆都必须依照每题 cutoff 构建/取版本，不能先吸收未来信息再仅过滤原文 ID。

**Evoking User Memory: Personalizing LLM via Recollection-Familiarity Adaptive Retrieval，ICLR 2026**，即 RF-Mem。[官方会议页](https://iclr.cc/virtual/2026/poster/10008269)，[全文](https://arxiv.org/html/2603.09250)。§2.3 的语义簇分支和有限轮扩展，提供无需检索 LLM 的代表根选择先例。此前已研究过，本次主要细读其分支与路由机制。其相似度/熵路由并不能证明证据充分，高相似 query echo 仍可能缺历史理由；这里不直接复制其路由或与论文准确率横比。

## 4. 方案 A：预算受控的多目标搜索，无新增检索 LLM

第一版保留原 R 和四项评分，单独测试调度。目标是让有限预算既能比较少数不同目标，又能留下深入机会。

1. **先严格固定根列表和顺序，再单独研究代表根。** 首个 E1a 使用与对照相同的初始根列表、次序和原 A 信号，仅改变开根/深入的额度与分时调度。后续 E1b 再从已有候选池选例如 6 个代表目标；保留 dense 第一名，其余用已有 embedding 的语义差异选择。这些根仍然都来自可见历史，且须保持问题相关性，不能只追求不同。E1b 的收益与 E1a 分开报告。
2. **前期明确给开根动作额度。** 以通常剩余的 23 次条件 ANN 为开发初值：6 次试探不同根、13 次深入、4 次留给中期新根/新线索。4 次在中期释放，不能拖到最后只开根而无力跟进。这些数字是待验证的初值，不是论文最优参数；初始实际消耗不同则按剩余额度缩放。
3. **把一次工作切小。** 一个调度单元至多 1 次新 ANN 和一小批完整四项测量，例如最多消耗 24 个新的任务内唯一集合额度。不能只限制 ANN：当前一个根还会扫描整个 initial_pool。未完成的候选扫描应保留游标，后续恢复不重复 ANN；没有扫完不能宣布“所有 singleton 都非正”。四项评分仍要完整可审计。
4. **未访问目标不与所有正 A 后继直接争一个 heap。** 先由开根/深入预算决定动作类别，再在类别内部按原信号选状态，同时设置每目标连续工作上限，避免重复候选形成无限优先权。首个调度消融不同时增加新的收益分数；按新增证据或单位成本收益调度留作后续比较。
5. **同样保留 36 ANN、512 搜索集合、512 选择集合的总约束。** 为覆盖和深入都预留集合额度；按原逻辑预算计费，跨任务暖缓存不等于免费。记录同一目标花了多少 ANN、集合评分以及产生多少最终保留的新证据。

初版不必实现完整 MCTS。用明确的动作与预算规则，足以检验“原先没有机会比较其他目标”这一假说；之后才考虑对收益/成本做更复杂估计。原 R 下找到更高分集合是过程指标，不能据此宣称答案更好。

## 5. 方案 B：正 activation 用于探索，条件贡献决定保留目标

使用已经得到的四个分数记录并区分三个事件：交互增强 A、新目标边际 M_e、新前提边际 M_G。每条记录无需额外评分。

可先单独测试两个规则：

- **保留原目标的高优先级分支**要求 `A>0` 且 `M_e>0`；再单独测试是否加入 `M_G>0`，不要一次混入所有门槛。
- 当 `M_e<=0` 而 PG 已有价值时，保留 PG 为独立候选；后续试验允许以 G 中的新线索开根，而不强迫整个搜索始终携带 e。前者是共同归档修复，后者是明确的新搜索机制。

不建议把所有当前负边际状态永久删除。真实互补可能需要多步才能出现，硬门槛会剪掉这样的路径；可以在方案 A 的有限探索份额里容纳浅层试探，但不让它与已验证有收益的分支享有无限同等预算。这个保留规则同样需要消融。

这里的“贡献”始终是**对 R 的贡献**。只要 R 仍然可能排斥原因历史，这个规则就只是减少错误锚定，不能完成语义修复。当前 `context_marginal` 对照已跑过且未更好，所以不能把换成上下文边际包装为已有胜出的答案。

## 6. 方案 C：用有出处的信息需求覆盖选择证据

这是更有希望修复“相关历史被拒绝”的方向，借鉴 SETR 的具体流程。第一步只换最终选择器，冻结候选池与搜索；验证有效后再让缺失信息驱动检索，便于定位增益来源。

### 6.1 先形成可检查的证据需求

需求必须由公开 query 与任务说明所支持；整个在线选择流程不能读取任何答案选项、gold label 或依赖隐藏题型标签。需要区分两个版本：首版采用一次 SETR 式联合调用，模型同时看到 query 和候选池，需求识别可能受候选影响；若要求需求严格独立于候选，则先做一次 q-only 调用并冻结结果，再做证据映射，是两次调用。两种版本不能混报成本或独立性。

例如询问偏好改变原因，需要核对的是历史态度/经历、可支撑变化解释的事实、当前变化；若当前变化已由 query 给出，不必为了重复它占据证据预算。推荐类问题不强行套用这三个槽位。

需求可以表示为“要找到哪些历史事实”，而不是先猜一个答案再找支持。每项标为已支持、缺失或存在阶段/对象歧义。

### 6.2 给需求映射原文，不让模型补写原因

每条支持关系保存 `requirement_id, source_id, 原文证据, 时间/阶段, 支持或冲突状态`。区分“原文明示”与“多条事实支持的推断”：允许跨历史组合推理，但推断必须列出支持来源，不能伪装成用户原话；仅凭先后关系或泛泛的“用户可能因为……”不足以确认因果，歧义保留为 unknown。字符串引用存在可以机械核验，但语义支持是否成立仍需人工抽检。

flashcards 案中，“weren't conducive to deep learning”能够填历史原因；重复当前问题只能填当前表态，不能自动填历史原因。也不把所有 query 同文记忆一律删除：同一条记录的其他内容可能有独立事实，且日志中 16 个只选回声的案例仍有 14 个答对。

### 6.3 整组选取，同时允许替换

在相同 token 上限内，优先覆盖回答必需的信息项，再避免冗余。对必须联合理解的证据使用小组映射，而非假定每个需求都能由单条记忆独立回答。先得到完整候选集合，再允许有界的删除/替换；不要求每次加入都提高旧 relevance。

这一步可以先用一次提示式 set selection，而非重新造一个未经校准的 0–1 U 分数。输出所选原始 source IDs、支持关系和仍缺的信息即可。完整性审查不过则保留可解释的部分证据，不得虚称充分。

### 6.4 验证后再让缺口驱动条件检索

例如从“继续围绕 m94 当前表态找相似文本”改为“找此前使用 flashcards 的体验及放弃理由”；如果新证据引出另一事件/阶段，允许更换检索线索。最终 reader 仍接收原始历史，不以模型写出的解释替代原文。

**成本边界：** 提示式方法无需参数训练，但改变当前检索侧零 LLM 的设计。首个固定池实验可限制为 1 次集合选择/证据映射调用；加入计划和中途复核后，可将每题上限预设为 2–4 次，另计 tokens、耗时和费用。这是本项目建议的预算，不是论文测得的成本。

若坚持检索侧不增加 LLM，也不训练新模型，方案 A/B 可以先做；但仅依靠当前 R 和字符串去重，不能声称已解决“历史理由是否对回答有用”的语义判断。

## 7. 实验顺序与否证条件

| 阶段 | 只改变什么 | 保持什么 | 看什么才算支持假说 |
|---|---|---|---|
| E0 | 确定性的实现修复作为共同基线 | 旧机制 | 归档/解析等工程问题不再混入机制收益 |
| E1a | 开根与深入调度 | 初始根列表/次序、R、原 A、reader、总预算 | 覆盖扩大后，支持答案的新证据及配对正确率是否提高；只多开根不够 |
| E1b | 代表根选择 | E1a 的调度与其余设置 | 收益是否来自更合适的代表根，而非暗中改变预算或评分 |
| E2 | M_e 门槛；随后独立测试 pivot | 调度、评分器与其他设置 | 减少携带负贡献 target，且未明显损害多步互补任务 |
| E3 | 固定候选池的需求—证据集合选择 | 召回/搜索输出、reader、token 上限 | 已召回历史的支持覆盖与保留率提高，并带来稳定回答收益 |
| E4 | 缺失证据驱动检索、带时间的历史支路 | 已验证选择流程和总资源约束 | 新增检索真正补足缺口；全流程成本仍可接受 |

E1a 与 E3 可以并行验证，初期不要把调度、评分、记忆表示和 reader 一起替换。E2 是容易实施的机制对照，不应因为改动小就预设它最有效。

已经看过的 261 题用于开发和机制说明，不作为新方案的未见确认集。开发样本既包含历史原因损害例，也包含原方法救回例和普通正确例。按 persona / 重复问题关系隔离确认集，避免把同一经历的近似题分到两边。

最终共同报告：同题正确率与救回/损害、任务成功覆盖、每目标双预算、根覆盖、证据支持/保留、最终 reader tokens、新增 LLM 调用与总成本。语义标注器需对照人工小样本；它给出的“充分”不能自作正确率。

同一实际 reader 请求应统一复用生成观测，或在预声明的配对重复设计下运行；不因某一次答错临时追加重试。当前日志中 dense/dense_rerank 相同 payload 仍有标签分歧，必须避免把这种波动归到检索变化上。

如果覆盖显著改善但答案没改善，不能宣布调度成功；如果 R 提升却历史支持下降，应停止进一步优化该代理目标；如果需求选择器经常编造因果或错配阶段，应回到证据映射验证，而不是追加搜索预算。
